# 评测及发布口径

三个回放案例来自 2026 年 11 月 18–19 日的同配置对照。原始组和组合组各完成 201 题，其他拆分对照中止。[评测计数](../data/metrics.json)记录了这两组的结果。README 的通过率采用三个业务域的等权平均。

两组在同一台机器运行，每题固定路由到同一个 2B 服务位置。模拟用户模型为 Qwen3.5-27B GPTQ INT4，原始与后训练 2B 都用 BF16，温度均为 0，种子为 300。沿用 τ²-bench 的官方任务和评分。报告采用固定的三域 201 题评测子集。评测按请求直接启动，完整复现性校准未结束。

案例是从 24 个失败转成功任务中选出的展示案例。回放依据六条实际轨迹里的工具调用、工具返回和官方评分制作。配对成功是官方奖励等于 1 且没有评测异常。主口径保留评测异常条目，并按失败计入固定分母。两组共有三道相关异常题；共同排除后，原始组通过 85/198，组合组通过 91/198。

## 训练流程

先让 27B 教师在训练侧 Telecom 环境里完成交互，并保留通过官方评分的 41 条多轮轨迹。用 VeRL SFT trainer 和 LoRA 在 Qwen3.5-2B 上做冷启动，仅监督客服回复和工具调用。已采用的配置包括 LoRA rank 16、alpha 32，学习率 1e-5，训练 2 个 epoch，上下文上限 10,240 token。

从 SFT adapter 开始跑普通 GRPO，以官方任务奖励为反馈，用 vLLM 生成多条工具交互轨迹。对照实验复用 DAPO 的动态采样思路过滤无组内奖励差异的样本组。这里用于展示的检查点来自普通 GRPO。训练题和评测题按任务 ID 分开。

另一轮独立的评测使用温度 0.5 的客服侧解码，并比较了原始、SFT 和两种强化学习方案。该轮未加手册。

| 方案 | 总通过 | 三域等权分 |
| --- | ---: | ---: |
| 原始 2B | 83/201 | 44.32% |
| SFT | 89/201 | 47.75% |
| SFT＋普通 GRPO | 95/201 | 49.90% |
| SFT＋DAPO 动态采样 | 91/201 | 47.00% |

README 的手册组采用项目方提供的分域计数，Telecom 52/122、Retail 38/63、Airline 9/16，合计 99/201，三域等权平均 53.06%。这组计数的逐题记录未包含在本仓库的回放归档中。

## 上游

- [τ²-bench](https://github.com/sierra-research/tau2-bench) 提供评测环境、原始任务和官方评分，采用 [MIT 许可](https://github.com/sierra-research/tau2-bench/blob/main/LICENSE)。
- [MERA-Evolve](https://github.com/yh-yao/MERA-Evolve) 提供小模型蒸馏、训练与推理的参考流程。
- [KnowWhenToHandOff](https://github.com/JaspinXu/KnowWhenToHandOff) 是项目早期的工程参考。

本仓库公开项目说明、静态业务手册、汇总指标、案例摘要和回放生成器。复现模型训练需准备上游代码及训练环境。

工作台回放由 `data/cases.json` 和 `data/product-replay.json` 生成。手机、订单和行程界面是工具日志的状态重建。四个阶段按业务步骤对齐，对话为摘要，阶段间隔用于阅读。
